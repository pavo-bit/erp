# SSVM ERP Remediation Decisions

Updated: 2026-10-31

1. Preserve existing local edits in `docker-compose.yml` and `ssvm-backend/Dockerfile`; they were present before this remediation and were not reverted.
2. Remove the confirmed CSRF bypass and weak fallback rather than preserving a knowingly disabled security boundary. Cookie-authenticated unsafe requests must provide the double-submit token. Login and payment webhooks remain explicitly exempt; bearer-only requests are exempt only when no auth cookies accompany them.
3. Private document bytes must not be served from an unauthenticated static path. Downloads now go through document ID, school and student checks and a confined filesystem path.
4. Retention policy creation/listing is school-scoped for school administrators; global retention execution is restricted to SUPER_ADMIN pending a broader governance permission model.
5. Manual late-fine generation is limited to authenticated finance/admin roles and one school at a time. Automated cross-school execution must use an explicitly authorized worker.
6. Do not claim full-phase completion or assign a completion percentage without an accurate requirement inventory and test evidence.
7. Remove the tracked backend `.env.backup` from the active tree and do not print its values. PostgreSQL/JWT/Razorpay webhook credentials require rotation; no Git history rewrite was performed.
8. Remove the legacy admin seed script. Demo seeding now requires an explicit non-production flag plus a supplied admin email and unique password, and refuses production.
9. Remove placeholder Razorpay credentials. Payment creation/verification now fails closed when provider secrets are absent, and signature comparison is constant-time.
10. CSRF executes before route authentication. Its double-submit token uses a stable browser context rather than `req.user`, which is unavailable at validation time; a per-user identifier here would mismatch tokens generated by authenticated handlers.
